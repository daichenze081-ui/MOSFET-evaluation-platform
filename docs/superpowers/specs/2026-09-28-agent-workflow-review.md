# 器件分析 Agent 整体思路校对稿

日期：2026-09-28

状态：用户已确认，进入分阶段实施；各项实际能力以使用文档及实施记录为准。
用途：汇总本轮讨论，作为确认后实施的依据。与早期设计表述冲突时，以本稿经确认的内容为准。

## 1. 当前目标与优先级

建设本地可调用的器件分析能力，保留稳定的 Python / JSON 接口，随后由 agent 调度这些工具。先把数据判断、回归补齐与关联分析做可靠，再扩展对话调度和原因推断。

主路径：客户提供 Spec，系统分析已有数据、补齐必要缺失指标，并给出合格情况、异常位置和关联线索。

常用场景按优先级排列：

1. 已有完整或部分实测数据，按 Spec 检查并分析异常。
2. 已有部分实测，利用适用的既有回归模型补齐缺失指标，形成综合判断。
3. 没有实测时，使用匹配的 COMSOL 数据作为替代证据，或提供明确标注的模型预测。
4. 新设计探索：评估参数微调的预期影响；无实测支持时，结果属于预测评估。

可选后续路径：客户明确需要时，评估暂定 Spec 的可制造性，生成修订建议。当前不实施，不改变主路径中的客户 Spec。

## 2. 本轮明确采用的场景

- 同一制程量级、相同器件结构类型中的微小改进。
- 用户给出的尺寸改变量为 **0.5 nm**，不是缩小到原来的 50%。相关参数可能约为原来的 85%～90%；以逐项实际输入为准，不自动给所有尺寸套用同一比例。
- 测量方式沿用已知方法或客户提供的方法，电流采用**绝对电流**。
- 新器件拥有新的 ID，不要求它曾出现在训练样本中。模型适用性由参数、结构和条件决定。
- 小幅变化默认优先尝试复用旧模型；仍检查实际覆盖，不能仅根据“只改了 0.5 nm”宣称一定适用。
- 当前分析范围到异常关联为止，原因判断样本库与根因推断后续另建。

## 3. 身份、来源与记录规则

### 3.1 器件与测量分离

`device_id` 标识实体器件，不标识某一次测量。同一器件在不同温度、偏置等条件下 ID 不变；不同实体器件使用不同 ID。

设计版本、批次、测量条件、记录版本分别保存。新制造器件与旧方案通过设计版本关联，不能为了复用模型而复用旧实体 ID。

### 3.2 来源隔离

业务优先级为：有效实测 > 匹配的 COMSOL > 合成/回归估计。

存储上分开保存实测、COMSOL 和合成/估计；合成数据与回归估计仍保留不同来源标签。统计、训练准入及证据追溯保持隔离。

优先级在同一指标且定义、条件、器件或设计映射可比时生效，不能用不匹配的高优先级数据覆盖匹配证据。有效实测超限不能被仿真或预测推翻。

原始缺失值不回写为实测值。回归补齐只进入本次分析结果，记录模型版本、输入和来源，不自动作为真实训练标签。

### 3.3 同一器件多份记录

正式分析以库中明确选定的有效记录及版本为准。重复、冲突记录需要可追溯的选择规则；不能靠导入顺序或字典覆盖决定采用哪条。

文件阶段也遵守这一规则：使用已选定记录的输入清单，未解决的重复记录明确报错。后续 SQL 化不能改变这一语义。

## 4. 主链路

```text
输入：器件参数 + 条件/测量方法 + 曲线或指标 + 客户 Spec
  ↓
核对身份、来源、单位、条件及记录版本
  ↓
从已有曲线提取指标，逐指标检查有效性
  ↓
对已有有效数据直接执行 Spec 判断
  ↓
有缺失指标，或需要新旧模型对比？
  ├─ 否 → 异常汇总与关联分析
  └─ 是 → 检查旧模型适用性 → 对已测指标进行预测偏差检查
                                  ↓
                     对可支持的缺失项生成预测补齐
                                  ↓
                  综合 Spec 判断 + 异常汇总与关联分析
  ↓
输出：一份报告 + JSON + 明细表 + 可追溯证据
```

模型不可用只影响预测与补齐，不阻断已有有效实测的判断。缺少 Spec 阈值时不自行生成阈值；可以展示数据，但不能给该项合格结论。

## 5. 缺失、无效与预测必须分开

| 类型 | 定义 | 本轮处理 |
| --- | --- | --- |
| 缺失 | 没有该指标，也无法从已有曲线提取 | 尝试适用的补齐路径 |
| 无效 | 有记录但不符合当前使用条件，例如非有限数值、提取失败、条件不匹配 | 保留值与原因，不静默替换 |
| 预测 | 模型计算的估计值 | 标注 predicted，检查适用性后参与相应判断 |
| 有效但超限 | 数据有效，但不满足 Spec | 作为 FAIL 证据，不能当异常数据删除 |

预测是来源属性，不天然等于无效。某一指标缺失或无效，不抹去其他指标的有效证据。上下文错误可能影响多个指标，需按实际影响范围标记。

第一轮补齐针对 MISSING，不自动覆盖 INVALID。无效实测的替代估计另行扩展，并同时保留原始质量问题。

## 6. 回归模型的职责与使用条件

冻结模型是已经训练完成、版本与参数固定的回归模型，并不是另一种模型原理。紧凑模型描述模型形式，冻结描述版本状态，两者不冲突。

本轮复用已有回归底层，不因新 device_id 自动重新训练。模型负责预测关系；agent 负责检查适用性、调用、比较证据和解释结果。

使用前检查：

1. 结构类型及相关工艺/材料背景是否兼容。
2. 几何、温度、偏置、指标定义是否满足模型要求。
3. 输入参数范围及组合是否有训练或验证支持。
4. 实际变化的变量是否被模型表达。固定宽度模型不能直接解释宽度变化，固定温度模型不能自动预测新温度。
5. 模型版本、验证记录和输入参数是否可追溯。

绝对电流保持原定义；不擅自转换为单位宽度电流，也不未经验证按尺寸比例缩放。

只有合格样本训练出的模型，可用于其覆盖范围内的响应预测，但不能直接代表失效边界、完整生产分布或根因概率。

### 6.1 已测指标对模型的检查

同一指标分别比较“实测—Spec”和“实测—预测”：

| 实测满足 Spec | 实测与预测一致 | 解释 |
| --- | --- | --- |
| 是 | 是 | 指标合格，模型获得新证据支持 |
| 否 | 是 | 指标不合格，变化符合模型预期 |
| 是 | 否 | 指标合格，但模型存在未解释偏差 |
| 否 | 否 | 指标不合格，同时需要审查模型适用性 |

偏差阈值采用已有独立验证依据或明确配置；没有依据时只报告偏差，不虚构“一致/异常”的量化界限。接近零的指标不盲目使用相对误差。

已测指标吻合不能证明未测指标必然准确；已测指标明显偏离时，缺失项预测需要降为参考或暂不采用。

### 6.2 补齐顺序与边界

先从已有原始曲线提取，再考虑具有明确器件/设计及条件映射的 COMSOL 证据，最后使用适用的回归估计。仿真补充仍标注 COMSOL，不伪装成实测或回归预测。

模型不支持、输入不足或适用性检查失败时，保留缺口及理由。局部校准、自动重训与模型自动发布不纳入下一轮；未来新增时需独立验证，不用同一批数据自证准确。

## 7. 一份报告中的综合判断

用户看到一份报告、一张核心指标表、一个综合结论。预测值直接写为 `0.02 A (predicted)`；需要追溯时可展开模型信息。

建议核心列：指标、用于判断的值、来源、Spec、判断、模型预测、实测与预测偏差。只有实际存在比较依据时才显示偏差。

综合结论规则：

- 存在有效原始数据超限：不满足当前 Spec，即使其他指标缺失或预测通过。
- 必需项全部由有效原始证据覆盖且通过：满足当前 Spec，并明确证据来源。
- 包含可信预测补齐且全部通过：预计满足当前 Spec，列出预测项；是否用于正式验收由客户规则决定。
- 仅预测项超限：预计不满足，明确对应预测项，不称为实测确认失败。
- 必需项无法补齐、预测支持不足或边界不确定：整体待确认；已确认的失败仍保留。

如有经过验证的预测区间，区间跨越 Spec 边界时不只看中心值判通过。没有可靠区间时明确误差证据的限制，不编造置信度。

底层保留原始判定与综合判定依据，便于追溯；不要求用户阅读两份报告。加入预测后的通过比例不能冒充实测良率。

## 8. 异常分析做到什么程度

本轮支持：

- 指标超限位置、方向、幅度及裕量。
- 与模型预期及可比较历史数据的差异。
- 分来源、条件、几何参数、批次的超限统计。
- 多指标共同超限及其样本依据。
- 数据不足、混杂变量与缺失测量的明确说明。

指标超限率分母为该指标有效受检数；共同超限率分母为相关指标均有效受检数。展示样本量，预测与原始证据分别可识别。

关联不等于原因。多个参数同步变化时，只能指出参数组合的关联，不能擅自分配各参数的因果贡献。一个新器件只能支持个体比较，不能单独形成稳定的异常概率估计。

本轮不输出物理根因概率，不将“异常覆盖率”称为“导致异常的概率”。后续原因样本库需包含异常表现、上下文、已确认原因、验证过程及处理结果。

## 9. 可选路径：Spec 可制造性评估

仅保留未来入口概念，客户提出需要后再细化和实施。

用途：利用代表性实测估计理论与实际的系统偏差及制造波动，在客户应用约束内比较候选 Spec。

边界：

- 不自动改变正在使用的客户 Spec。
- 回归均值不是工业允许波动；不能直接用一条拟合曲线或均值 ±3σ 制定验收标准。
- 需要有效的不合格样本、跨批次数据、测量质量与过程稳定性证据。
- 预测补齐和仿真扫描不能直接作为真实制造波动样本。
- 输出修订建议及其代价，也允许结论为“标准合理，工艺能力不足”。
- 经应用验证及客户确认后，才形成新的 Spec 版本。

本轮不为这条路径增加空接口或自动放宽逻辑。

## 11. 确认后的下一轮实施顺序

1. 核实旧模型输入、支持条件、验证信息与输出指标，确定适用性检查规则。
2. 将模型预测接入本地诊断接口，增加逐指标实测/预测偏差与采用理由。
3. 实现仅对缺失项的补齐，保存原始状态、模型版本、输入及预测来源。
4. 扩展现有单份报告与 JSON，增加综合结论及证据完整性，不改变原始数据统计口径。
5. 使用现有数据的遮蔽副本验证流程；使用独立验证数据评估补齐表现。

既有回归算法尽量少改；无必要不重写训练系统。读取已有本地完整数据，私有输入和真实数据产物保留在本地忽略目录，不写入公共示例或文档。

## 12. 验收与校对重点

### 实施验收

- 新 device_id、适用参数可以调用旧模型，无需先入训练集。
- 完整数据不因接入补齐而改变原有判定。
- 部分缺失时仍保留有效实测失败，预测不能覆盖它。
- 预测值有明确标注，不能自动转为实测或训练真值。
- 模型不适用时保留缺口，原始数据分析仍能完成。
- 同一器件不同条件、不同器件相同数值均不被错误合并。
- 无有效数据、零分母、未知误差均明确表达，不生成虚假比例或置信度。
- 遮蔽补齐验证不泄露被遮蔽值；训练样本只验证集成流程，不能当作独立泛化验证。
- 原始输入、历史报告和已生效 Spec 不被覆盖。

### 请重点校对的约定

1. 主路径仍是客户 Spec 下的诊断、补齐和关联分析。
2. 新器件优先复用适用旧模型，不因 ID 新而重训。
3. 一份报告展示 predicted，综合结论说明预测依赖。
4. 本轮补齐缺失值，不静默替换无效数据。
5. 当前不推断根因，不输出根因概率。
6. Spec 修订仅保留为未来可选路径。
7. 本稿已确认；下一轮交付旧模型对比、缺失补齐及单份综合报告，其余能力按上述边界推进。
