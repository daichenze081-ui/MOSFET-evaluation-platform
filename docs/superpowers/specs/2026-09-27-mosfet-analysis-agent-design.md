# MOSFET 数据诊断与指标补齐 Agent：整体方案汇总

日期：2026-09-27

范围：内部分析助手；本文件汇总已确定的业务方向、判断规则与分阶段实施方案。它是目标设计，不表示所有能力已经实现。

## 1. 产品定位与优先级

系统以客户数据和客户 Spec 为依据，帮助用户判断是否符合要求、定位更常出现异常的指标与条件，并在数据不完整时利用已有模型补齐缺失指标，给出有明确证据标注的综合判断。

| 优先级 | 主要场景 | 输入 | 核心输出 |
| --- | --- | --- | --- |
| 第一 | 已有数据的异常诊断 | 实测数据、条件、客户 Spec；无实测时可采用 COMSOL 数据 | 指标判定、异常频率、集中条件、共同超限、具体器件与证据 |
| 第二 | 部分数据缺失时的完整评估 | 已有数据、客户 Spec、适用模型 | 缺口清单、补齐值、逐项来源、综合结论与补测建议 |
| 第三 | 新器件、新设想的初步评估 | 设想参数、适用模型、可选客户 Spec | 预测指标、适用范围、预计符合情况与验证需求 |

数据诊断与预测评估是两种判断逻辑。完整数据的 Spec 检测和异常统计不依赖模型训练。回归模块的近期首要用途是缺失指标补齐，新设想预测作为后续用途保留。

### 当前开发基线（2026-09-28 补充）

先完成本地分析程序、配置、数据管理和报告，从第一阶段起保留可供 agent 调用的结构化 Python 接口。接入语言模型作为后续适配工作，不作为本地功能建设的前提。

开发与回归验证直接沿用项目所有者在本地完整版中已有的 Spec、测量合约、COMSOL 曲线和冻结模型，无须重新要求项目所有者提供客户标准或新数据。客户自定义 Spec 是产品支持的输入能力；当前开发使用既有案例 Spec，两者不冲突。

本地输入通过配置引用外部数据根目录，运行产物写入被 Git 忽略的输出目录。公共代码不硬编码开发机路径，也不因本地验证而复制原始私有数据进入版本控制。缺失指标、来源冲突和重复导入等场景由测试构造，原始输入保持不变。

## 2. 数据身份、来源与隔离

### 2.1 器件身份

- `device_id` 识别器件，不识别一次测量。同一器件在不同条件下保持相同 ID。
- 条件单独记录，包括适用的温度、偏置、扫描设置及相关上下文；条件内容变化必须可追溯，不能悄悄修改历史记录的含义。
- 分开管理器件、条件、测量或仿真记录、记录修订版本。
- 同一来源内保留当前有效版本和历史版本。当前取数至少明确器件、条件、来源和选中记录。
- 曲线与由该曲线提取的指标建立派生关系，不能因为表现形式不同被误认成两个独立样本。

### 2.2 来源优先级

**实测 > COMSOL > 合成预估。** 合成预估内部继续区分模型估计、拟合预测和合成示例的生成方式。

各来源分开保存、选择、统计和追溯。第一版可沿用 SQLite，通过来源约束与访问层实现逻辑隔离；不以数据库迁移作为前置目标。

| 环节 | 规则 |
| --- | --- |
| 导入 | 原始来源必填；来源不明的历史数据不能直接推定为实测 |
| 更新 | 更新形成可追溯版本，不能把一条预估记录改标签变成实测 |
| 去重 | 区分同一记录重复提交与不同器件数值相同；内容相同不能单独作为丢弃器件的依据 |
| 训练 | 数据集显式指定来源；第一版不跨来源混训，分别维护模型及来源信息 |
| 预测 | 即使训练数据来自实测，预测值仍属于预估数据 |
| 统计 | 实测、COMSOL、预估分别统计，不共用异常率分母 |
| 证据 | 每个采用值能够追溯到记录、原始数据或模型版本 |

防止重复导入与防止训练/验证泄漏分开处理。不同器件的相同指标可以保留，但复制的训练曲线不能更换 ID 后充当独立验证证据。

### 2.3 以库内数据为准

正式分析使用已通过准入并选定的库内记录。外部新文件先经过校验、入库和版本选择，再参与正式分析。

常规诊断先匹配器件与条件，再在适用来源中按优先级选择。多个候选无法按既定规则唯一选择时，返回歧义，不以导入顺序暗中覆盖。

无实测时可以使用 COMSOL 作为替代分析依据，报告明确标明仿真结论。有实测超限时，仿真或预估通过不能覆盖该事实。

## 3. 客户 Spec 与判断边界

客户提供自己的判断标准，系统严格执行；项目现有 Spec 仅作为示例。

- Spec 保存客户或项目归属、标识、版本、适用条件、指标、单位、比较方向和阈值。
- Spec 缺失时，可以展示数据、提取指标和对比，但不输出合格结论。
- 阈值、单位或适用条件存在歧义时先补充明确，agent 不自行制定阈值。
- Spec 变更产生新版本和新评价，原始数据及历史评价保留。
- 同一数据在不同客户标准下可以有不同结论，每个结论必须绑定实际使用的 Spec。
- 数据质量检查与 Spec 判定分离：有效数据可以 FAIL；数据无效不等于器件 FAIL。

本方案中的“补齐”指补齐 Spec 所需但缺失的指标数据，**不指补齐客户未提供的标准或阈值**。

## 4. 主线一：已有数据的异常诊断

### 4.1 流程

选择库内数据和条件 → 绑定客户 Spec → 检查数据质量 → 逐指标判定 → 形成整体判定 → 汇总异常 → 按条件定位 → 展示器件与原始证据。

第一版主要定位两类问题：

1. 指标位置：Ioff、SS、Vth、Ion、gm 等哪些指标更常超限。
2. 条件位置：异常集中在哪些温度、偏置、批次或几何范围；仅使用实际存在且可核对的分组信息。

保留曲线证据入口，后续再细化扫描区间定位与物理机制分析。指标超限和共同出现不直接等于已证明的物理根因。

### 4.2 逐指标判定

每条明细至少包含器件、条件、记录版本、指标、值、单位、Spec 规则、阈值、判定、超限程度、来源及证据引用。

逐指标区分通过、超限、缺失、无效和不适用。有效性检查针对该指标及其必要上下文进行；一个指标不可用时，不抹去其他有效指标的判定证据。

只要求客户启用的 Spec 规则及其必要上下文；模型训练和曲线提取的额外输入要求由各自模块管理。

存在有效且适用的直接数据超限即可确认相应规则不满足；全部必需项有效且通过才能给出完整直接评价通过。没有已确认超限但存在缺口时，整体直接评价不完整。

### 4.3 异常统计口径

| 统计量 | 定义 | 用途 |
| --- | --- | --- |
| 指标超限率 | 指标超限数 / 该指标有效受检数 | 哪项指标最常不满足 Spec |
| 失败样本覆盖率 | 出现该指标超限的失败样本数 / 本组已确认失败样本总数 | 排查该指标覆盖多少已知失败 |
| 仅该指标超限数 | 该指标超限、其他必需规则全部有效且通过的样本数 | 找出表现较单一的失败样本 |
| 共同超限数 | 两项或多项同时超限的样本数 | 发现经常共同出现的问题 |
| 超限程度 | 指标相对适用阈值的偏离情况，同时保留原单位偏差 | 区分频繁小幅异常和少见严重异常 |

每个比例同时展示分子、分母、缺失数量和数据来源。分母为零时返回不可计算，不能填为 0%。失败覆盖统计同时显示失败组中该指标的有效检查覆盖情况；缺失不能当作通过。

同一器件可能多项超限，因此覆盖率之和可以超过 100%。共同超限比例以双方均有效受检的范围计算，并明确分母。

第一版称为“本批次超限率/异常频率”，不直接宣称未来器件的失效概率或物理根因概率。COMSOL 扫描点的超限比例描述所选设计点，不冒充真实制造群体的发生概率。

### 4.4 分组与排序

- 固定 Spec、来源和可比条件后统计；不同条件按各自适用标准分组。
- 在同一条件内，同一器件采用选定记录计一次；复测与修订不能人为增加器件样本量。
- 跨条件总览区分器件数与器件-条件观测数；同一器件的多次测试不当成多个独立器件。
- 频率排名同时展示受检覆盖和样本量，不将样本少的高比例直接解释成可靠的高风险结论。
- 单独展示异常频率与超限严重程度，第一版不合成为无法解释的综合评分。
- 当前代码选出的最大归一化超限项改为“最大相对超限项”的展示语义，不能命名为已确认根因。

## 5. 主线二：缺失指标补齐与综合判断

### 5.1 补齐顺序

1. **先提取：** 已有原始曲线满足要求时，调用现有提取算法。结果标为由相应来源曲线提取，不标为回归预测。
2. **再查适用的直接替代数据：** 库内存在同器件、同条件的 COMSOL 等候选时，按来源规则选择并逐项标注；未能确认对应关系时不自动拼接。
3. **再模型估计：** 对确实缺失的指标，选择来源明确、条件和参数范围适用的已有模型进行估计。
4. **局部拟合后置：** 用部分实测调整个体参数作为后续增强，需要单独验证参数约束是否充分；不默认每次补齐都重训或改变全局模型。

既有有效直接数据优先，补齐只处理缺失项，不改写原始记录。数据无效或质量异常时保留问题原因；不能用预测掩盖已发现的数据问题。

模型适用性至少检查所需输入是否齐全、单位和条件是否匹配、几何范围是否支持、模型验证状态是否允许本次使用。不能仅凭“能算出数字”接受补齐；已有数据与模型明显不一致时，应返回不适用或需要进一步验证的原因。

### 5.2 逐项来源与存储

补齐值保存在分析结果层，关联源记录、模型版本、输入快照、估计方法与执行 ID。原始字段继续保留缺失状态。

综合评价允许组合不同层级的证据，但每个指标必须有明确来源。这是显式的补齐流程，不是将混合数据重新标成实测。

- 实测曲线提取值属于实测派生结果；COMSOL 曲线提取值属于仿真派生结果。
- 模型估计值不进入实测异常率，不作为真实标签回流训练。
- 后续补测到达后，创建基于新数据的评价，保留旧估计及其历史结论，并可比较估计与实际偏差。

### 5.3 综合结论

| 证据情况 | 综合输出 |
| --- | --- |
| 全部必需项均有有效实测且通过 | 实测符合 Spec |
| 适用的有效实测中存在超限 | 实测不符合 Spec；其他缺口单独列出，补齐不能推翻该结论 |
| 没有实测，使用完整 COMSOL 数据评价 | COMSOL 数据符合或不符合 Spec，不表述为实测结论 |
| 已有实测通过，缺失项补齐后也通过 | 综合估计符合 Spec，含补齐项，待实测确认 |
| 已有实测通过，补齐项超限 | 综合估计不符合 Spec，列出风险来自仿真还是模型估计 |
| 模型不适用或仍有必需项无法补齐，且无已确认的直接超限 | 判断不完整，列出缺口与原因 |
| 已发现超限但仍有缺口 | 保留已确认的超限结论，同时标注评价覆盖不完整 |

每次结果分别表达：整体判定、直接证据结论、来源构成、补齐项、评价完整程度及待验证项。不得只返回一个掩盖证据差异的 PASS/FAIL。

### 5.4 补齐后的异常分析

报告分开展示“已观测异常”和“补齐后的潜在异常”。实测、仿真、预估分别统计，不能用模型补齐结果扩大实测样本数或实测超限数。

补测建议优先指向：综合结论依赖的关键缺失项、估计超限项、已有数据与模型明显不一致的器件。建议必须能关联具体指标、器件和证据。

## 6. 辅助路线：新设想评估

保留现有拟合、预测、冻结模型及验证基础，减少底层改动。优先增加模型使用边界和结果来源的明确表达。

当前代码主要支持固定温度、固定宽度下的长度和氧化层厚度变化。已有多温度数据可以直接用于分组诊断，但预测未覆盖温度或全新器件形状属于后续模型扩展，不能通过接口包装视为已支持。

新设想结果应列出预测值、模型版本、训练来源、适用范围及验证状态；客户提供 Spec 时再进行预计符合性评价。

## 7. Agent 的职责与技术边界

采用单 agent 调用固定分析工具的方式。agent 负责理解需求、明确分析范围、询问缺失的必要参数、调用工具和解释结果；数值计算、Spec 判定、来源选择和统计由程序实现。

建议工具职责：

| 工具能力 | 输出 |
| --- | --- |
| 查询数据与证据 | 器件、条件、来源、选中记录及原始证据 |
| 检测 Spec 与识别缺口 | 逐指标判定、直接评价、缺失及质量问题 |
| 补齐指标 | 每项补齐值、来源、模型依据、失败或不适用原因 |
| 分析异常 | 指标排名、条件分组、共同超限、代表器件 |
| 生成报告 | 固定运行结果的报告与证据引用 |
| 拟合和预测 | 候选模型、验证结果、预测值及适用范围 |

工具统一返回执行 ID、状态、结构化数据、错误/告警、证据与产物引用。数据写入、候选训练和模型发布分开，尝试拟合不自动切换当前模型。

运行结果绑定选中记录、Spec 与合约快照、模型和算法版本。数据库保存结构化结果，HTML 作为用户阅读入口。耗时训练逐步移出长写事务，并增加任务状态、幂等和过期任务发布检查。

## 8. 当前基础与需要矫正的工作

已有基础包括 SQLite 存储、指标提取、Spec 规则、超限明细、基础异常汇总、拟合预测、模型版本和对比报告。

| 优先工作 | 当前问题或缺口 | 目标 |
| --- | --- | --- |
| 修正去重 | 不同器件的相同指标可能被当成重复 | 保留独立器件，同时维持导入幂等与验证隔离 |
| 修正取数 | 同器件曲线和指标表可能按入库顺序覆盖 | 显式按条件、来源、版本及关联关系选择 |
| 来源贯穿 | 数据形式、存储位置和原始来源存在混用 | 每项数据及模型保留原始来源与派生关系 |
| 逐指标评价 | 整行无效可能掩盖局部有效证据，必需指标过于固定 | Spec 驱动的局部评价与独立整体结论 |
| 异常分析 | 现有主要超限项易被误解为根因，分组及共现能力不足 | 明确统计含义与排查优先级 |
| 补齐流程 | 缺少统一的缺口识别、适用性判断及混合证据结论 | 显式、可追溯的补齐与综合评价 |
| 结果追溯 | 运行 ID 与结构化历史结果需要加强对外提供 | 每个结论可通过运行 ID 复核 |

## 9. 分阶段实施与交付

### 第一阶段：可直接使用的数据诊断

完成保证统计正确所需的身份、来源、去重和取数修正；实现客户 Spec 驱动的逐指标判定、缺口清单、异常频率、条件分组、共同超限与器件证据。同步定义并实现本阶段的结构化请求与结果接口，由 CLI 和报告共同调用，为后续 agent 预留真实可调用的服务边界。

交付：不依赖回归或 agent 的诊断流程，能够回答“本批次哪些指标最值得优先排查，依据是什么”。

### 第二阶段：补齐与综合判断

增加原始曲线优先提取、适用模型估计、逐项来源、综合结论和潜在异常报告。沿用现有回归底层；针对明确能力缺口再做局部调整。

交付：不完整输入可以得到可解释的整体评估，无法补齐时清楚返回原因，估计不污染直接数据。

### 第三阶段：Agent 封装

将前两阶段已经可调用的本地接口适配为 agent 工具，提供任务结果查询，接入单 agent，完成查询、诊断、补齐、解释与报告对话闭环。补充必要的运行日志、幂等和任务状态。

交付：自然语言请求与直接调用分析程序得到一致的数字、统计范围、来源和结论。

### 后续增强

局部参数拟合、更广的温度与形状预测、曲线区间定位、结合证据的物理机制假设、具备统计前提的未来风险估计。多 agent、复杂前端及大规模数据库迁移不作为当前交付前提。

## 10. 验收要求

| 场景 | 必须满足的结果 |
| --- | --- |
| 不同器件指标相同 | 均被保留，不误去重 |
| 同一记录重复导入 | 不重复增加样本或训练 |
| 同器件多条件、多来源 | 分别保存和选择，来源互不覆盖 |
| 数据导入顺序变化 | 在记录选择相同的前提下，结果不因顺序改变 |
| 缺少客户 Spec | 不自动采用示例阈值作合格判定 |
| 客户修改 Spec | 新评价可查，旧数据及旧评价保留 |
| 部分指标缺失 | 有效指标仍被评价；未知项不计为通过 |
| 多项共同超限 | 每项均计入相应统计，分母清楚，允许覆盖率重叠 |
| 有原始曲线可提取 | 优先提取，不多走模型估计 |
| 实测 FAIL、模型 PASS | 实测超限事实保持不变 |
| 补齐后全部通过 | 明确属于含估计项的综合判断 |
| 补齐项超限 | 明确风险来源，不计入实测异常率 |
| 模型超范围或输入不足 | 返回不适用/无法补齐，不强行生成有效值 |
| 后续补测到达 | 新实测用于新评价，历史补齐与结论可追溯 |
| 拟合失败或重复提交 | 旧模型保持，错误可查，不重复发布 |

补齐效果使用训练集之外的完整数据进行遮蔽验证：隐藏部分已知指标或曲线，保留实际部署时可用输入，评估补齐误差、覆盖率、误放行和误拒绝。禁止被遮蔽目标通过其他派生字段泄漏；同一器件的相关记录按验证设计保持隔离，分别报告不同来源、条件与缺失模式下的结果。

验收同时验证两条能力：程序能正确执行规则；agent 能忠实表达程序结果，不能省略补齐标记或夸大结论。
