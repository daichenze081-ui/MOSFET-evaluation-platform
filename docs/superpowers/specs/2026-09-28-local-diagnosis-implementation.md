# 本地诊断第一轮实施

依据：已确认的整体方案。开发输入沿用本地完整版的既有 Spec、合约和 COMSOL 数据，通过运行配置引用，不要求额外客户样例。

## 交付边界

本轮交付独立的本地诊断入口：曲线或指标表 → 逐指标 Spec 检查 → 异常汇总、分组与共同超限 → JSON/CSV/HTML。同步提供可直接调用的 Python 接口和请求 JSON Schema。

既有 evaluate/fit/predict/update 保持原有调用方式。新诊断入口采用独立的逐指标语义，不用宽松的诊断规则替代严格的训练准入。回归补齐与存储迁移属于下一轮工作，不提供空实现或虚假成功接口。

## 实施步骤

1. 分离指标表的格式读取与严格准入，使诊断可以保留缺失值；来源必须显式声明，声明冲突时拒绝。
2. 曲线诊断复用现有采样、Vth、SS、gm 和 Ion 一致性算法；缺少某类曲线时保留其他可独立提取指标。
3. 新增逐规则与逐指标判定，保留 FAIL/PASS/MISSING/INVALID 和整体评价完整程度。仅启用 Spec 中的规则。
4. 新增按来源隔离的指标超限率、失败覆盖率、仅该指标超限、成对共同超限及几何分组。
5. 新增诊断工作流与 Python 服务，返回严格 JSON，保存运行 ID、输入哈希与 Spec/合约快照。每次运行有独立结果目录。
6. CLI 调用同一服务；增加使用文档与合成回归测试，使用外部既有数据验收。

## 验证重点

- 不完整数据仍保留有效超限证据，未检查项不算通过。
- 双边阈值按一项指标统计，避免 Vth 重复计数；零分母为 null。
- 不同来源分别汇总；重复身份要求用户先选择记录，不能重复计数。
- 不改变客户阈值；缺失 Spec 无法生成合格判断。
- 没有目标曲线时不伪造数值；Ion 校验曲线缺失或冲突不能产生有效 Ion。
- JSON 无 NaN，HTML 转义输入，结果文件不覆盖输入。
- 沿用现有算法时，完整曲线的诊断判定与原评价一致。
- 完整现有测试继续通过；本地外部数据仅用于忽略目录中的运行产物。
